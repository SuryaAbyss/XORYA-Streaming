Cumulative Layout Shift — Score: 1.142

CRITICAL FAIL

This is your single biggest problem. A CLS of 1.142 is catastrophically bad — the acceptable limit is 0.1, and anything above 0.25 is considered "poor." Your score is over 11× the limit. What this means visually is that entire sections of your page are jumping and shifting around after the initial paint, which is a terrible user experience and will tank your Google Search ranking.

🔴 Main Culprit — The Entire Content Container Shifts
The report found 4 layout shift events, with the biggest one having a score of 1.0 (the max possible for a single shift). The element responsible is the div.home-page container — essentially your whole homepage content block below the hero. This suggests the hero section (YouTube embed + backdrop image) loads and then pushes everything down.
🔴 Images Without Explicit Dimensions
Two images are reported without explicit width and height HTML attributes:

1. Your logo: /logo.png — the XORAYA navbar logo has style="height:50px; width:auto" but no HTML attributes.
2. Hero movie title logo: /t/p/w500/39qu7nY1DgTfFLmpDPVB6hkDcTV.png — only CSS dimensions, no HTML dims.

Without HTML dimensions, the browser cannot reserve space for the image before it loads, so everything below shifts when it appears.
🟡 Web Font Load Shift
One shift is directly linked to the Google Inter font loading from fonts.gstatic.com. When the Inter font loads, it slightly changes text dimensions which nudges elements down. The fix is one CSS line.

How to fix CLS:

1
Add width + height to all img tags. Even when using CSS to control display size, the HTML attributes let the browser pre-allocate space before the image loads. Example: <img src="..." width="500" height="750" style="width:100%;height:auto">
2
Reserve space for the hero section. Give your hero div an explicit min-height or use aspect-ratio: 16/9 so nothing below it jumps when the YouTube iframe and backdrop load.
3
Fix font loading. Add font-display: optional to your @font-face or use font-display: swap in your Google Fonts URL: append &display=swap (you already have this from the ?display=swap query, but also preconnect to fonts.gstatic.com).
4
Fix section heading opacity animation. Your h2.movie-row-title elements start at opacity: 0; transform: translateX(-20px). The browser paints them at zero height. Either initialize them with real height, or use visibility: hidden instead of opacity:0 to preserve their layout box.

04

246 Non-Composited Filter Animations

HIGH

The report found 246 animated elements where the animation cannot run on the GPU compositor thread. Every one of your interactive-movie-card elements uses filter: blur(0px) as part of its animation. The problem is that filter animations force the browser to repaint on the CPU main thread, potentially causing jank and contributing to layout instability.

🟡 All 246 Movie Cards Use Filter Animation
The class .interactive-movie-card is animating filter: blur() alongside opacity and transform. The transform and opacity are compositable (GPU-friendly), but adding filter forces the entire element off the compositor. Remove blur from the animation and use only opacity + transform, which are fully GPU-composited.
/* REMOVE this from your card animations: */ filter: blur(0px); /* <-- causes main thread repaint */ /* KEEP only these (fully GPU composited): */ opacity: 1; transform: none; /* If you need blur on hover, contain it with: */ .interactive-movie-card { will-change: transform, opacity; }
